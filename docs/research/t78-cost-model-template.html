Recommendation

  • Up to ~100 Light or Medium users, every serverless option is effectively free. The DynamoDB, Cosmos and Firestore free tiers come to $0–3/mo, against Cloudflare's $5 Workers Paid base. Instance-priced Postgres costs $10–14/mo from the start. Heavy users leave the free tiers sooner: at 100 Heavy users DynamoDB is ~$7, Cosmos ~$10 and Firestore ~$23 a month.
  • From 1,000 users up, Cloudflare D1 + Workers is the cheapest real database. On the Medium profile at 1M users it costs about $12.7k/mo. The hyperscaler options run $21k–34k/mo. The gap comes from free egress and cheap per-row reads. D1 is SQLite, so the current schema and queries carry over almost unchanged.
  • D1 caps each database at 10 GB, so at scale it needs one database per user or per team. Durable Objects with SQLite give the same model (one SQLite per tenant) and add websocket push, which replaces polling.
  • The $5 Workers Paid base covers about 530 Medium users. The 30M CPU-ms allowance runs out first (at 5 ms per request); the 10M-request allowance lasts to about 890 users.
  • D1 allows 50,000 databases per account by default (raisable on request) and 1 TB of storage per account. Per-user databases hit the count cap at 50k users, so plan per-team databases or Durable Objects before then. Storage passes 1 TB at ~120k Medium or ~12k Heavy users; the model adds a $5 account per extra TB (Medium × 1M = {{MEDIUM_1M_D1_ACCOUNTS}} accounts). Durable Objects SQLite bills rows at the same rates with cheaper storage, so the D1 column is an upper bound for that route.
  • Cheapest first step: a nightly per-user SQLite snapshot to R2, for backup and new-device restore. At 1,000 Medium users that is ~6 GB and ~30k writes a month, inside R2's free tier, so about $0.
  • Among the hyperscalers the winner depends on how much data each user has. Light: Cosmos DB serverless is cheapest at every size (1M users: ~$9.2k vs ~$13.7k for Azure Postgres), Firestore close behind. Medium: Cosmos is cheapest up to 100k users (~$2.4k vs ~$2.7k); managed Postgres wins only at 1M (Azure Flexible ~$21.3k vs Cosmos ~$24.3k). Heavy: managed Postgres wins from 1k users (~$131 vs DynamoDB ~$146, Cosmos ~$154), because a flat instance price beats per-request billing once each user's data is dense. Cosmos cells marked † are past serverless limits and would need provisioned throughput. At Heavy × 1M (~{{HEAVY_1M_TIB}} TiB) a single Postgres would have to be sharded, so treat that row as a lower bound.
  • Object storage on its own (R2 or S3 holding the SQLite file) is the cheapest way to back up or sync for one person. It is not a database: there are no concurrent writers and no per-field merge, so it cannot support shared boards.
  • The biggest cost lever is polling, not storage. The local app polls every 10 s. The model below assumes 60 s in the cloud. Push (websockets / SSE) would cut most of the read and request cost.
